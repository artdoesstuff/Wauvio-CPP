Kanji

The kana parser only knows sounds, so kanji are first converted to hiragana (kanji.hpp), and the result goes through the normal parser. Three ways to say how a kanji is read, in this order:

  1. Ruby, written in the lyric — 漢字《かんじ》: the reading belongs to the whole kanji run before 《. ｜漢字《かんじ》 (｜ marks where the base starts) also works for kana bases. Ruby always wins: use it for anything the dictionary reads wrongly (行って, 今日, 人気 …).
  2. The dictionary (longest match). Entries may carry okurigana, so 食べる, 出す or 行って can be listed as words, and a plain stem entry (食 → た) lets 食べ / 食べた / 食べない work with the kana left as written. The built-in list is small and favours readings common in song lyrics.
  3. Nothing — a kanji without a reading is skipped and reported by Singer::diagnostics(). Compounds that could only be read piece by piece (三人 → さん + ひと) are reported too, since that is usually the wrong reading.
  • Singer::kanji_dictionary() returns the singer’s own KanjiDictionary (a copy of the built-in list): add(kanji, reading) (reading in hiragana or katakana; returns false if either side is empty), load_text, load_file, find, size. Singer::load_kanji_dictionary(path, &err) loads a file with one kanji reading per line (space or tab separated; blank lines and # comments ignored). Valid lines load even if others fail; the error names the first bad line.
  • KanjiDictionary::builtin() is the shared built-in list; kanji_to_kana(text, dict, &notes) converts a string directly.
  • Not covered: choosing a reading from context (this is a dictionary, not a language analyser) and Shift-JIS kanji in MIDI lyric events (use UTF-8 lyrics for kanji). Kanji settings are not stored in .wvc voicebanks.

ParseOptions

  • merge_long_vowels (true) — “おう/えい/ああ” inside one lyric become a single long vowel.
  • cute (false, v2+) — baby-talk softening: s/z/t/d/n/r palatalise.
  • kanji (true, v3), kanji_dictionary (null = the built-in list), kanji_notes (optional sink for “no reading” messages) — see Kanji. Set kanji = false to ignore kanji like any other unknown symbol.
  • particles (false, v3) — a trailing は/へ is read as わ/え. Independent of the flag, a trailing ^ marks a single は/へ as a particle anywhere (は^, へ^).

Model types

  • Vowel A I U E O; Cons (kana rows): None, K, G, S, Z, T, D, N, H, P, B, M, R, Y, W.
  • Mora — c, v, palatal, geminate, nasal, longv, force (foreign overrides F, TI, DI, TS, J, CH, SH, S, Z, V), labial, ng, weight, cons_scale, text.
  • Surf — the realised consonant classes the synthesiser builds: K G T D P B TS CH J S SH Z H HY FU N NY M R Y W GEM MORAIC_N NG V (v3 adds V = [v] for ヴ). surface(mora) resolves the allophone; is_voiced, is_obstruent_unvoiced.
  • decode_lyric_bytes() — decodes MIDI karaoke lyric bytes (UTF-8, ASCII or a minimal Shift-JIS kana subset).
  • parse_kana, parse_romaji, parse_phonemes, parse_lyric.

struct Mora
    Cons  c        = Cons::None;
    Vowel v        = Vowel::A;
    bool  palatal  = false;   // yo-on: きゃ しゅ ちょ ...
    bool  geminate = false;   // っ
    bool  nasal    = false;   // ん (moraic nasal)
    bool  longv    = false;   // ー or merged long vowel: continue previous vowel
    // Foreign-sound overrides (ふぁ てぃ つぁ ...): force a particular surface
    // consonant in place of the one implied by (c, v).
    enum class Force : uint8_t { None, F, TI, DI, TS, J, CH, SH, S, Z, V } force = Force::None;
    bool  labial   = false;   // V2: w-glide between consonant and vowel (くぁ ぐぁ ...)
    bool  ng       = false;   // V2: velar nasal [ŋ] (phoneme input "ng" / ガ行 nasalisation)
    float weight   = 1.f;     // V2: relative share of the note's time (lyric syntax さ[0.7]ん[0.3], phoneme "@0.7")
    float cons_scale = 1.f;   // V2: consonant strength multiplier (phoneme "*1.5")
    std::string text;         // source text of the mora (UTF-8), for diagnostics

struct ParseOptions
